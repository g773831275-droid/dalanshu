# 微信扫码登录概要设计

## 1. 目标

用户在 PC 登录页使用微信扫码，完成注册或登录。

认证方式：微信开放平台网站应用，渠道标识为 `wechat_open`。

## 2. 身份模型

```text
sys_user.user_id（平台用户）
    └── sys_social（微信身份）
```

平台以 `sys_user.user_id` 作为永久用户标识，微信只是登录方式。

| 标识 | 来源 | 用途 |
|---|---|---|
| `source` | 系统定义 | 固定为 `wechat_open` |
| `app_id` | 微信开放平台 | 区分微信应用 |
| `open_id` | 微信返回 | 用户在单个应用内唯一 |
| `union_id` | 微信返回 | 同一开放平台主体下跨应用识别 |

身份唯一键：

```text
tenant_id + source + app_id + open_id
```

`union_id` 只用于跨应用匹配，不是全网唯一标识。

## 3. 数据设计

复用现有表，不新建业务表：

| 表 | 用途 |
|---|---|
| `sys_user` | 平台用户 |
| `sys_social` | 微信身份绑定 |
| `sys_user_role` | 默认角色 |
| `sys_client` | `social` 授权配置 |
| `sys_tenant` | 租户信息 |
| `sys_login_infor` | 登录日志 |

`sys_social` 使用以下字段：

| 字段 | 内容 |
|---|---|
| `user_id` | 平台用户 ID |
| `tenant_id` | 所属租户 |
| `source` | `wechat_open` |
| `open_id` | 微信 OpenID |
| `union_id` | 微信 UnionID，可为空 |
| `auth_id` | `source:app_id:open_id` |
| `nick_name` / `avatar` | 微信昵称和头像 |
| Token 相关字段 | 微信授权令牌 |

当前 `sys_social` 没有 `app_id`。如果只使用一个微信网站应用，可暂不增加；接入多个微信应用前增加：

```sql
app_id varchar(64) default null comment '第三方应用ID'
```

OAuth `state` 保存在 Redis，不建立二维码状态表。

## 4. 业务流程

```text
微信扫码授权
  → 后端取得 open_id / union_id
  → 查询 sys_social
      → 已绑定：登录对应 user_id
      → 未绑定：创建 sys_user，再创建 sys_social
  → 记录登录日志
```

查询顺序：

1. 按 `source + app_id + open_id` 精确查询。
2. 未找到且有 `union_id`，查询同主体已有绑定。
3. 仍未找到，创建新用户。
