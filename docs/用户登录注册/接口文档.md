# 用户登录注册接口文档

## 1. 公共约定

- 除头像上传外均使用 `application/json`。
- 默认租户由后端注入，客户端不传 `tenantId`。
- 认证请求体沿用项目 API 加密机制。
- 已登录接口请求头：`Authorization: Bearer <access_token>`。
- 通用响应：`{ "code": 200, "msg": "操作成功", "data": ... }`。
- 手机号使用 E.164 格式；邮箱按小写匹配。

## 2. 注册登录与恢复

### 2.1 获取图形验证码

`GET /auth/code`

响应数据：

```json
{
  "captchaEnabled": true,
  "uuid": "验证码唯一标识",
  "img": "Base64 图片"
}
```

### 2.2 发送邮箱验证码

注册页应先调用：

`GET /auth/email/check?email=user@example.com`

响应 `data=true` 表示可以注册，`data=false` 表示该邮箱已被注册。该接口只用于改善交互，注册接口仍会再次检查唯一性。

`GET /resource/email/code?email=user@example.com&purpose=register&uuid=xxx&code=12`

| 参数 | 必填 | 说明 |
|---|---|---|
| `email` | 是 | 邮箱地址 |
| `purpose` | 是 | `register` 或 `recover` |
| `uuid` | 是 | 图形验证码唯一标识 |
| `code` | 是 | 图形验证码答案 |

验证码必须按邮箱和用途分别保存，只能使用一次。恢复场景无论邮箱是否存在，都返回相同提示。

### 2.3 邮箱注册并自动登录

`POST /auth/register`

```json
{
  "clientId": "客户端标识",
  "email": "user@example.com",
  "emailCode": "123456",
  "password": "用户密码"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `clientId` | 是 | 启用的客户端标识 |
| `email` | 是 | 未注册邮箱 |
| `emailCode` | 是 | `purpose=register` 的验证码 |
| `password` | 是 | 密码，规则待确认 |

成功时创建普通用户并直接返回登录令牌。现有 `RegisterBody` 需要调整。

### 2.4 邮箱或手机号密码登录

`POST /auth/login`

```json
{
  "clientId": "客户端标识",
  "grantType": "password",
  "account": "user@example.com",
  "password": "用户密码",
  "uuid": "图形验证码标识",
  "code": "图形验证码"
}
```

`account` 可以是邮箱或已维护的手机号。现有密码登录按 `username` 查询，实施时需要改为按邮箱或手机号查询。

成功响应数据：

```json
{
  "access_token": "访问令牌",
  "refresh_token": "刷新令牌",
  "expire_in": 1800,
  "refresh_expire_in": 604800,
  "client_id": "客户端标识",
  "scope": "授权范围"
}
```

### 2.5 退出登录

`POST /auth/logout`

需要登录令牌，无请求体。成功后当前会话失效。

### 2.6 通过邮箱恢复密码

`POST /auth/password/recover`

```json
{
  "clientId": "客户端标识",
  "email": "user@example.com",
  "emailCode": "123456",
  "newPassword": "新密码"
}
```

验证码必须由 `purpose=recover` 产生。重置成功后注销该用户全部旧会话，不直接返回登录令牌。

## 3. 个人资料

### 3.1 获取当前用户与权限

`GET /system/user/getInfo`

返回当前用户 `user`、角色集合 `roles` 和权限集合 `permissions`。

### 3.2 获取个人资料

`GET /system/user/profile`

返回 `user`、`roleGroup` 和 `postGroup`。

### 3.3 修改个人资料

`PUT /system/user/profile`

```json
{
  "nickName": "昵称",
  "phonenumber": "+8613800138000",
  "sex": "2"
}
```

| 字段 | 说明 |
|---|---|
| `nickName` | 最长 30 个字符 |
| `phonenumber` | 可选，E.164 格式，不能与其他有效用户重复 |
| `sex` | `0` 男、`1` 女、`2` 未知 |

首期不允许通过此接口修改邮箱。

### 3.4 登录后修改密码

`PUT /system/user/profile/updatePwd`

```json
{
  "oldPassword": "旧密码",
  "newPassword": "新密码"
}
```

旧密码必须正确，新密码不能与旧密码相同。修改成功后建议注销其他会话。

### 3.5 修改头像

`POST /system/user/profile/avatar`

请求类型：`multipart/form-data`，文件字段为 `avatarfile`。

成功响应数据：`{ "imgUrl": "头像访问地址" }`。

## 4. 首期暂不提供

- 短信验证码和手机号找回密码。
- 邮箱换绑。
- 微信等第三方登录。

## 5. 本地邮件配置

首期固定使用 QQ SMTP。在 IDEA 的 `DromaraApplication` 运行配置中加入：

```text
DALANSHU_MAIL_PASSWORD=QQ邮箱SMTP授权码
```

发件邮箱已固定为 `858178877@qq.com`。`DALANSHU_MAIL_PASSWORD` 是该 QQ 邮箱生成的 SMTP 授权码，不是 QQ 登录密码，也不能提交到 Git。
