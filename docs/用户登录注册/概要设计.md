# 用户登录注册概要设计

## 1. 首期范围

- 用户使用邮箱验证码注册，注册时强制设置密码。
- 注册成功后自动登录。
- 登录支持“邮箱 + 密码”；用户维护手机号后，也支持“手机号 + 密码”。
- 账号恢复仅支持通过已验证邮箱重置密码。
- 手机号为可选登录别名，首期不发送短信、不用于账号恢复。
- 使用后端默认租户，前端不展示、不传租户标识。
- 暂不包含微信登录、短信验证码和后台用户管理。

## 2. 账号模型

- `sys_user` 保存平台账号、密码、邮箱、可选手机号和基础资料。
- 邮箱是首期唯一可信身份凭证；同一默认租户内唯一。
- 手机号维护后可作为登录别名，同一默认租户内唯一，但未短信验证。
- `user_name` 是系统内部唯一用户名，不由用户填写，也不直接展示邮箱或手机号。
- `sys_social` 留给以后保存微信等第三方身份。

## 3. 数据字段

### 3.1 必须调整

| 字段 | 调整 | 原因 |
|---|---|---|
| `phonenumber` | 扩为 `varchar(32)` | 支持国际号码及国家区号 |
| `user_name` | 后端自动生成 | 邮箱注册时仍需满足现有用户模型 |

手机号统一保存为 E.164 格式，例如 `+8613800138000`；邮箱去除首尾空格并统一按小写比较。

### 3.2 建议新增

| 字段 | 类型 | 说明 |
|---|---|---|
| `register_source` | `varchar(20)` | 首期固定为 `email`，以后可扩展 |

邮箱只在验证码校验成功后写入，因此首期不需要额外增加 `email_verified` 字段。

### 3.3 内部用户名规则

使用 `u_ + 唯一编码`，例如 `u_01JABC...`。不直接拼接邮箱或手机号，避免泄露个人信息和超过现有用户名长度。

## 4. 主要规则

1. 注册必须提交邮箱、邮箱验证码和密码。
2. 邮箱验证码按用途隔离：`register` 只能注册，`recover` 只能重置密码。
3. 验证码设置有效期、单次使用、发送限流、校验失败次数和图形验证码保护。
4. 邮箱已存在时提示“账号已注册，请直接登录或找回密码”。
5. 密码使用 BCrypt 保存，不得记录或返回明文。
6. 注册成功后创建会话，直接返回与登录接口相同的令牌数据。
7. 登录字段统一为 `account`，后端识别邮箱或手机号并校验密码。
8. 用户维护手机号后可用手机号登录；手机号重复时拒绝保存。
9. 未验证手机号不能用于找回密码、敏感操作或证明账号归属。
10. 新用户暂定分配“普通用户”角色，可浏览全部文章并发表评论。
11. 停用、逻辑删除、租户停用的用户禁止登录。
12. 用户注销或删除后，邮箱和手机号允许重新注册，但必须创建新的 `user_id`，不恢复旧数据。

## 5. 主要流程

### 5.1 邮箱注册

完成图形验证码 → 获取注册用途的邮箱验证码 → 提交邮箱、验证码和密码 → 注入默认租户 → 校验邮箱唯一性 → 生成内部用户名 → 创建用户并分配普通用户角色 → 自动登录并返回令牌。

### 5.2 密码登录

完成图形验证码 → 输入邮箱或手机号及密码 → 注入默认租户 → 标准化登录凭证 → 查找用户 → 校验密码和状态 → 返回令牌。

### 5.3 邮箱恢复账号

完成图形验证码 → 向已注册邮箱发送恢复验证码 → 提交邮箱、验证码和新密码 → 校验后更新密码 → 注销该用户全部旧会话 → 返回重置成功，用户重新登录。

无论邮箱是否存在，发送验证码接口对外使用相同提示，避免泄露平台注册用户。

### 5.4 个人资料

用户可修改昵称、性别、头像和手机号。手机号保存前需要标准化并检查唯一性。邮箱作为账号恢复凭证，首期不开放自行换绑。

## 6. 首期接口

### 6.1 注册登录与恢复：7 个

| 方法 | 地址 | 用途 |
|---|---|---|
| GET | `/auth/code` | 获取图形验证码 |
| GET | `/auth/email/check` | 检查邮箱是否可注册 |
| GET | `/resource/email/code` | 发送注册或恢复用途的邮箱验证码 |
| POST | `/auth/register` | 邮箱验证码注册并自动登录 |
| POST | `/auth/login` | 邮箱/手机号加密码登录 |
| POST | `/auth/logout` | 退出登录 |
| POST | `/auth/password/recover` | 邮箱验证码重置密码 |

### 6.2 个人资料：5 个

| 方法 | 地址 | 用途 |
|---|---|---|
| GET | `/system/user/getInfo` | 获取当前用户、角色和权限 |
| GET | `/system/user/profile` | 获取个人资料 |
| PUT | `/system/user/profile` | 修改昵称、性别和手机号 |
| PUT | `/system/user/profile/updatePwd` | 登录后修改密码 |
| POST | `/system/user/profile/avatar` | 修改头像 |

首期合计 **12 个接口**。
