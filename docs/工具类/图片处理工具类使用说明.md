# TOS 图片处理工具类使用说明

## 1. 适用范围

项目使用火山引擎 TOS 私有桶保存原图，通过 `x-tos-process` 在读取时动态生成缩略图和 WebP 图片。数据库和业务表始终保存原图的 `ossId`，不保存带签名的临时 URL，也不为每个尺寸重复保存对象。

图片处理入口统一为：

- 固定规格：`org.dromara.common.oss.enums.OssImageStyle`
- 业务调用：`ISysOssService#getImageAccessUrl(Long, OssImageStyle)`
- 签名实现：`OssClient#createPresignedGetUrl(String, Duration, OssImageStyle)`

业务模块不得接收前端传入的宽度、高度、质量或完整 `x-tos-process` 字符串，避免出现无限尺寸组合、缓存碎片和不可控的数据处理费用。

## 2. 固定图片规格

| 枚举 | 规格编码 | 处理方式 | 当前用途 |
|---|---|---|---|
| `AVATAR_128` | `avatar_128` | 128×128 居中裁剪、WebP、绝对质量 82 | 信息流、评论、消息中的小头像 |
| `AVATAR_256` | `avatar_256` | 256×256 居中裁剪、WebP、绝对质量 85 | 个人主页、个人资料头像 |
| `POST_FEED_720` | `post_feed_720` | 宽度 720、等比缩放、WebP、绝对质量 80 | 首页、搜索、用户/圈子帖子列表 |
| `POST_DETAIL_1440` | `post_detail_1440` | 宽度 1440、等比缩放、WebP、绝对质量 85 | 帖子详情及圈子置顶图片 |
| `CIRCLE_CARD_720X405` | `circle_card_720x405` | 720×405 居中裁剪、WebP、绝对质量 82 | 圈子列表和导航卡片 |
| `CIRCLE_BANNER_1600X700` | `circle_banner_1600x700` | 1600×700 居中裁剪、WebP、绝对质量 85 | 圈子详情页横幅 |

这些规格目前直接固化为 TOS 图片处理表达式，不依赖控制台预先创建同名图片样式。规格编码用于日志、文档和业务语义，不会发送给前端作为可修改参数。

## 3. 业务模块调用

```java
import lombok.RequiredArgsConstructor;
import org.dromara.common.oss.enums.OssImageStyle;
import org.dromara.system.service.ISysOssService;

@RequiredArgsConstructor
public class PostApplicationService {
    private final ISysOssService ossService;

    public String feedCover(Long ossId) {
        return ossService.getImageAccessUrl(ossId, OssImageStyle.POST_FEED_720);
    }

    public String detailImage(Long ossId) {
        return ossService.getImageAccessUrl(ossId, OssImageStyle.POST_DETAIL_1440);
    }
}
```

需要原图或普通附件下载地址时继续使用：

```java
String originalUrl = ossService.getAccessUrl(ossId);
```

## 4. 私有桶签名规则

当前 Bucket 为私有桶。`x-tos-process` 是 GET 请求的一部分，必须在生成预签名 URL 之前加入请求并参与签名，不能对已经生成的 URL 执行字符串拼接：

```text
错误：presignedUrl + "&x-tos-process=..."
正确：构建带 x-tos-process 的 GetObjectRequest，再生成预签名 URL
```

签名 URL 只是短期访问凭证，禁止保存到数据库、长期缓存或日志。业务表只保存 `ossId`，每次响应客户端时重新生成当前有效地址。

## 5. 降级行为

`getImageAccessUrl` 内置以下降级：

- GIF 返回原图，避免动态处理导致动画丢失或变成单帧。
- 非火山 TOS 的 S3/MinIO 配置返回原图，不附加 TOS 专用参数。
- `imageStyle` 为空时返回原图。
- 文件不存在时返回 `null`，业务层按现有规则决定占位图或异常。

前端应继续为图片提供加载失败占位图，不能把带签名 URL 当作稳定资源标识。

## 6. 上传限制

大蓝树用户端当前限制单张图片不超过 10MB，只允许 JPEG、PNG、WebP 和 GIF。TOS 基础图片处理对原图大小、格式和像素存在额外限制，因此不要放宽上传限制后直接依赖 TOS 兜底。

上传时保存原始图片，展示时按业务场景选择固定规格。后续如增加 HEIC 上传，需要先确认浏览器上传、TOS 处理和内容审核链路都支持，再修改白名单。

## 7. CDN 接入注意事项

当前 URL 由 TOS 私有桶直接签发。后续接入 CDN 时，建议切换为“CDN 私有桶回源 + CDN URL 鉴权”，并让缓存键包含固定规格、忽略仅用于鉴权且不影响图片内容的参数。

不要同时无规划地开启 TOS 图片处理和 CDN 质量压缩。若使用 CDN 质量压缩，应重新确定质量控制归属，避免重复压缩。

## 8. 验证

修改图片规格或签名逻辑后至少执行：

```bash
mvn -pl ruoyi-common/ruoyi-common-oss -am test -DskipTests=false
mvn -pl ruoyi-modules/ruoyi-system -am -DskipTests compile
```

真实桶联通测试默认跳过。需要验证 TOS 返回的内容格式与尺寸时，在具备测试对象和私密环境变量的环境中开启 `TOS_LIVE_TEST=true`，不得把 AK/SK 写入测试代码。

## 9. 新增规格的约束

只有出现新的、稳定复用的页面尺寸时才新增枚举。新增时必须同步：

1. 在 `OssImageStyle` 中增加固定处理表达式。
2. 在业务接口中选择新枚举，禁止由前端传枚举名称决定任意资源处理方式。
3. 更新本文的规格表和用途。
4. 增加或调整签名测试，并在真实图片上检查裁剪区域和清晰度。
