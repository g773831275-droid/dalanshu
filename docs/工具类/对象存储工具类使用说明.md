# 对象存储工具类使用说明

项目对象存储已统一接入火山引擎 TOS。业务代码不需要读取 Endpoint、Bucket、AK 或 SK，也不要自行创建 S3/TOS 客户端。

## 1. 业务模块如何选择调用方式

| 场景 | 推荐入口 | 是否写入 `sys_oss` | 业务表保存什么 |
| --- | --- | --- | --- |
| 用户上传、业务附件、头像、帖子图片 | `ISysOssService` | 是 | `ossId` |
| 根据附件 ID 下载、删除、获取访问地址 | `ISysOssService` | 使用已有记录 | `ossId` |
| 底层任务生成的临时对象，不需要附件记录 | `OssFactory.instance()` | 否 | 对象 Key（如确有必要） |
| 前端直传所需的短时签名 | `OssClient#createPresignedPutUrl` | 否，上传完成后需自行落库 | 对象 Key 或后续生成的 `ossId` |

一般业务功能应优先使用 `ISysOssService`。它不仅上传对象，还会保存原始文件名、对象 Key、存储服务商和扩展信息，并处理私有桶的临时访问 URL。

## 2. 推荐方式：注入 `ISysOssService`

在 Spring Bean 中使用构造器注入：

```java
import lombok.RequiredArgsConstructor;
import org.dromara.system.service.ISysOssService;
import org.springframework.stereotype.Service;

@Service
@RequiredArgsConstructor
public class PostAttachmentService {

    private final ISysOssService ossService;
}
```

业务模块需要能够依赖 `ruoyi-system`。底层 `ruoyi-common-*` 模块不要反向依赖 `ruoyi-system`；这类场景应把附件操作留在上层业务服务，或在明确不需要 `sys_oss` 记录时使用第 7 节的底层客户端。

## 3. 上传文件

### 3.1 上传 `MultipartFile`

```java
import org.dromara.system.domain.vo.SysOssVo;
import org.springframework.web.multipart.MultipartFile;

public Long uploadPostImage(MultipartFile file) {
    validateImage(file); // 业务层校验大小、MIME 类型和后缀

    SysOssVo oss = ossService.upload(file);
    return oss.getOssId();
}
```

`SysOssVo` 常用字段：

| 字段 | 含义 |
| --- | --- |
| `ossId` | `sys_oss` 主键，业务表应保存此值 |
| `fileName` | TOS 中的对象 Key，不是用户上传时的原文件名 |
| `originalName` | 用户上传时的原始文件名 |
| `url` | 当前可访问地址；私有桶时通常是短时预签名 URL |
| `service` | 实际使用的存储配置，目前为 `volcengine` |

不要把 `url` 当作永久地址保存。当前 Bucket 为私有桶，预签名 URL 会过期；业务表保存 `ossId`，展示时再查询新 URL。

### 3.2 上传本地 `File`

```java
import java.io.File;
import org.dromara.system.domain.vo.SysOssVo;

public Long uploadGeneratedReport(File temporaryFile) {
    SysOssVo oss = ossService.upload(temporaryFile);
    return oss.getOssId();
}
```

注意：当前底层上传实现会在上传结束后删除传入的本地文件。因此这里只能传临时文件，不要传仍需保留的业务源文件。如需保留，先复制到临时目录，再上传副本。

### 3.3 Controller 返回示例

```java
@PostMapping(value = "/attachments", consumes = MediaType.MULTIPART_FORM_DATA_VALUE)
public R<Long> upload(@RequestPart("file") MultipartFile file) {
    SysOssVo oss = ossService.upload(file);
    return R.ok(oss.getOssId());
}
```

上传前必须在业务接口中限制文件大小、允许的 MIME 类型和后缀。对象存储服务只负责保存文件，不能替代内容合规、安全扫描和业务校验。

## 4. 查询文件和获取私有访问 URL

私有桶访问地址应通过 `listByIds` 获取：

```java
import java.util.List;
import org.dromara.common.core.exception.ServiceException;
import org.dromara.system.domain.vo.SysOssVo;

public String getAttachmentUrl(Long ossId) {
    return ossService.listByIds(List.of(ossId)).stream()
        .findFirst()
        .map(SysOssVo::getUrl)
        .orElseThrow(() -> new ServiceException("附件不存在"));
}
```

当前 `listByIds` 会为私有对象生成约 120 秒有效的预签名 URL。`getById(ossId)` 主要用于读取数据库记录，不保证返回的 `url` 已刷新为可访问的预签名地址。

只需要批量 URL 时，也可以注入通用接口：

```java
import org.dromara.common.core.service.OssService;

private final OssService ossService;

String urls = ossService.selectUrlByIds("1001,1002,1003");
```

## 5. 下载文件

面向 HTTP 响应下载时，直接交给服务处理文件名、Content-Type、Content-Length 和输出流：

```java
import jakarta.servlet.http.HttpServletResponse;
import java.io.IOException;

@GetMapping("/attachments/{ossId}/download")
public void download(@PathVariable Long ossId, HttpServletResponse response) throws IOException {
    checkBusinessPermission(ossId); // 下载前校验当前用户是否有权访问该业务附件
    ossService.download(ossId, response);
}
```

不要只凭客户端传来的 `ossId` 下载。`sys_oss` 是公共附件表，业务接口必须先校验附件与当前业务数据、租户和用户的关系。

系统已有通用接口：

```text
GET /resource/oss/download/{ossId}
```

该接口受 `system:oss:download` 权限控制。面向普通用户的业务接口应自行实现业务授权，不应给普通用户开放管理端权限。

## 6. 删除文件

```java
import java.util.List;
import org.dromara.common.core.exception.ServiceException;

public void deleteAttachment(Long ossId) {
    checkCanDeleteAttachment(ossId);

    boolean deleted = ossService.deleteWithValidByIds(List.of(ossId), true);
    if (!deleted) {
        throw new ServiceException("附件删除失败");
    }
}
```

该方法会同时删除 TOS 对象和 `sys_oss` 记录。调用前应先检查是否仍被帖子、头像、工单等业务数据引用，并按业务需要先解除引用。

数据库事务不能回滚对象存储操作。涉及“写业务表 + 上传/删除对象”的流程，应设计补偿逻辑：数据库保存失败时删除刚上传的对象；对象删除失败时保留数据库记录并安排重试。

## 7. 底层方式：直接使用 `OssClient`

只有不需要 `sys_oss` 附件记录的基础设施场景才直接使用：

```java
import org.dromara.common.oss.core.OssClient;
import org.dromara.common.oss.entity.UploadResult;
import org.dromara.common.oss.factory.OssFactory;

OssClient client = OssFactory.instance(); // 当前租户的默认配置

byte[] content = "example".getBytes(StandardCharsets.UTF_8);
UploadResult uploaded = client.uploadSuffix(content, ".txt", "text/plain");

String objectKey = uploaded.getFilename();
String storageUrl = uploaded.getUrl();
```

`OssFactory.instance()` 使用当前租户启用的默认存储配置。通常不要在业务代码中写死 `OssFactory.instance("volcengine")`，否则后续切换默认存储时业务代码仍会绑定火山云。

### 7.1 指定对象 Key 上传流

```java
byte[] content = buildExportFile();
String objectKey = "exports/2026/report.xlsx";

UploadResult uploaded = client.upload(
    new ByteArrayInputStream(content),
    objectKey,
    (long) content.length,
    "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet"
);
```

流上传的 `length` 必须是准确字节数。自动生成对象 Key 时使用 `uploadSuffix`，并传入带点的后缀，例如 `.png`、`.pdf`。

### 7.2 下载到输出流

```java
ByteArrayOutputStream output = new ByteArrayOutputStream();
client.download(objectKey, output, length -> log.debug("文件大小: {}", length));
byte[] content = output.toByteArray();
```

大文件不要下载到 `ByteArrayOutputStream`，应直接写入 HTTP 输出流或文件输出流，避免占用大量堆内存。

### 7.3 删除对象

```java
client.delete(objectKey);
```

### 7.4 生成预签名 URL

```java
import java.time.Duration;
import java.util.Map;

String getUrl = client.createPresignedGetUrl(objectKey, Duration.ofMinutes(2));

String putUrl = client.createPresignedPutUrl(
    "direct-upload/example.png",
    Duration.ofMinutes(5),
    Map.of("source", "dalanbook")
);
```

预签名 URL 相当于短期访问凭证：有效期应尽可能短，不要写入长期缓存、数据库或日志。前端直传完成后，如该文件属于业务附件，后端仍需验证对象存在、归属正确，并补充对应的附件记录和业务关联。

## 8. 异常处理和安全要求

- 对象存储失败会抛出 `OssException`，业务层可统一转换为项目的 `ServiceException` 或业务错误码。
- 不要在异常、日志或接口响应中输出 AK、SK、完整签名参数和私密配置内容。
- 不要信任客户端提供的对象 Key、文件名、MIME 类型或 `ossId`；必须进行格式、权限和归属校验。
- 文件名展示使用 `originalName`，实际存储和下载定位使用 `fileName`（对象 Key）。
- 业务表优先保存 `ossId`，不要保存会过期的私有 URL。
- 批量删除前先完成业务引用检查；跨数据库与对象存储的操作需要补偿或重试机制。
