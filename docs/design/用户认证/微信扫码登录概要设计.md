# 微信扫码登录概要设计

> 文档类型：概要设计  
> 建设阶段：待排期  
> 接口清单：[大蓝树前后端接口汇总](../../api/大蓝树前后端接口汇总.md)

## 1. 建设目标

用户在 PC 登录页使用微信扫码完成大蓝树账号注册或登录。认证渠道使用微信开放平台网站应用，内部渠道标识统一为 `wechat_open`。

当前后端已有通用第三方授权、绑定和解绑能力，Vue 管理端已有对应调用；大蓝树 React 用户端的“扫码后直接注册或登录”流程尚未实现。

## 2. 身份模型

```text
sys_user.user_id（平台用户）
    └── sys_social（微信身份）
```

平台始终以 `sys_user.user_id` 作为永久用户标识，微信仅作为登录和身份验证方式。

| 标识 | 来源 | 用途 |
|---|---|---|
| `source` | 系统定义 | 固定为 `wechat_open` |
| `app_id` | 微信开放平台 | 区分微信网站应用 |
| `open_id` | 微信返回 | 用户在单个应用内唯一 |
| `union_id` | 微信返回 | 同一开放平台主体下跨应用识别 |

建议身份唯一键：

```text
tenant_id + source + app_id + open_id
```

`union_id` 只用于同一开放平台主体下的跨应用匹配，不能视为全网唯一标识。

## 3. 数据设计

优先复用 RuoYi 现有认证表：

| 表 | 用途 |
|---|---|
| `sys_user` | 平台用户主账号 |
| `sys_social` | 微信身份及授权信息 |
| `sys_user_role` | 新用户默认角色 |
| `sys_client` | `social` 授权客户端配置 |
| `sys_tenant` | 租户信息 |
| `sys_login_infor` | 登录日志 |

`sys_social` 需要保存 `user_id`、`tenant_id`、`source`、`open_id`、可选 `union_id`、昵称、头像和授权令牌。若接入多个微信网站应用，应补充 `app_id varchar(64)` 并建立上述组合唯一约束。

OAuth `state` 保存到 Redis，设置短有效期并在回调时单次消费，不建立二维码状态业务表。

## 4. 目标业务流程

```text
PC 获取微信授权地址和 state
  → 用户扫码并在微信确认
  → 微信回调后端
  → 后端校验 state 并换取 open_id / union_id
  → 查询 sys_social
      → 已绑定：登录对应 sys_user
      → 未绑定但可安全匹配：绑定已有 sys_user
      → 无匹配：创建 sys_user 和 sys_social
  → 分配普通用户角色并记录登录日志
  → 向 PC 页面发放一次性登录结果
  → PC 换取平台访问令牌和 refresh token
```

微信身份查询顺序：

1. 按 `tenant_id + source + app_id + open_id` 精确查询。
2. 未找到且存在 `union_id` 时，在同一微信开放平台主体内查询已有绑定。
3. 仍未找到时，按自动注册规则创建平台用户。

## 5. 与现有接口的关系

当前 `/auth/binding/{source}`、`/auth/social/callback` 和 `/auth/unlock/{socialId}` 服务于“已登录用户绑定或解绑第三方身份”。它们不能完整覆盖匿名用户在 PC 扫码后直接登录的流程。

扫码登录新增接口在方案确认和代码实现前只作为设计项，不写入接口汇总。实现时应满足：

- 获取授权地址时不由用户端传入可信租户标识，默认租户由后端决定。
- `state` 必须防重放、短时有效并与浏览器登录事务绑定。
- 微信回调不能直接在 URL 中暴露平台访问令牌。
- PC 端只能使用一次性票据换取平台令牌，票据使用后立即失效。

## 6. 安全与异常处理

1. 校验微信回调签名、授权响应、`state`、应用 ID 和回调域名。
2. 同一微信身份只能绑定一个有效平台账号；并发注册依赖数据库唯一约束兜底。
3. 账号合并必须再次验证已有账号身份，不允许仅凭昵称、邮箱或手机号自动合并。
4. 微信授权令牌加密保存，不写入业务日志。
5. 用户拒绝授权、二维码过期、回调失败和账号停用时给出可重试且不泄露账号信息的提示。
6. 解除绑定前必须确保用户仍有其他可用登录方式。

## 7. 待确认

1. 是否仅允许默认租户 `000000` 自动注册。
2. 新微信用户的默认角色、部门和内部用户名规则。
3. 已有邮箱账号与微信身份的绑定、冲突和合并规则。
4. 微信解绑、重新绑定以及账号注销后的身份保留规则。
5. 是否只接入一个微信网站应用；若不是，必须增加 `app_id` 字段和唯一索引。
6. PC 端扫码结果采用轮询、SSE 还是 WebSocket 通知。
