# 大蓝书前后端建设模块与范围

> 状态：范围讨论稿  
> 目的：先明确产品模块、职责边界、建设阶段和关键规则；本稿不包含表结构、字段设计和具体接口定义。

## 1. 产品目标

大蓝书首期围绕“用户加入兴趣圈子并分享真实经验”形成最小业务闭环：

```text
注册/登录
  → 浏览首页或搜索圈子
  → 进入圈子和帖子详情
  → 加入/关注感兴趣的内容
  → 发布帖子
  → 点赞、收藏、评论和回复
  → 运营人员审核与治理内容
```

首期优先保证内容生产、内容消费、基础互动和合规治理可用。复杂推荐算法、完整用户画像和精华体系放在产生足够真实数据后建设。

## 2. 范围划分原则

1. 用户端前端负责内容展示、交互流程和用户输入，不承载业务权限判断。
2. 业务后端统一提供用户、圈子、帖子、互动、审核等领域能力，Web、移动端和运营后台复用。
3. 运营后台负责管理、审核、配置和数据查看，不与用户端页面混用。
4. “删除”默认指逻辑删除或下架；合规证据、审核记录和操作日志不得随内容物理删除。
5. “推荐”和“置顶”是两个能力：推荐决定分发权重，置顶决定固定展示位置。
6. 帖子评论与评论回复使用同一套互动能力，通过层级关系区分，不分别建设两套接口。
7. 首页、圈子详情等页面的帖子列表复用统一的信息流查询能力，仅查询条件和排序策略不同。

### 2.1 已确认的一期决策

1. 用户关注关系、关注/粉丝列表及计数属于一期。
2. 首页和圈子详情的“关注”信息流属于一期。
3. 帖子草稿的保存、恢复和删除属于一期。
4. 话题隶属于圈子，帖子只能选择所属圈子下的话题。
5. 一期保留基础规则推荐，以支撑“推荐”分区；热点排行、个性化推荐及推荐算法平台属于二期。

## 3. 用户端前端模块

### 3.1 用户与账号

| 功能 | 内容 | 阶段 |
|---|---|---|
| 用户注册 | 邮箱验证码注册、设置密码、注册成功自动登录 | MVP |
| 用户登录 | 邮箱/手机号加密码登录、退出登录、会话失效处理 | MVP |
| 找回密码 | 通过已验证邮箱重置密码 | MVP |
| 我的中心 | 个人资料、头像、我的帖子、加入的圈子、收藏内容 | MVP |
| 账号设置 | 修改昵称、性别、手机号、密码 | MVP |
| 关注关系 | 关注/取消关注用户，查看关注与粉丝 | MVP |
| 消息通知 | 评论、回复、点赞、关注等站内通知 | 第二阶段 |
| 账号注销 | 用户主动申请注销及冷静期 | 待确认 |

用户认证的既有决策继续以 [用户登录注册概要设计](../用户登录注册/概要设计.md) 为准。本模块只引用其能力，不重复定义账号字段和认证协议。

### 3.2 首页与内容发现

#### 信息流快速切换

| 分区 | 定义 | 阶段 |
|---|---|---|
| 推荐 | 按发布时间、基础热度和运营权重进行规则排序 | MVP |
| 关注 | 用户所关注作者发布的帖子；未登录时引导登录 | MVP |
| 最新 | 按发布时间倒序展示可见帖子 | MVP |
| 精华 | 运营或圈子管理者评定的高质量内容 | 延后 |

#### 帖子浏览

- 瀑布流/列表浏览，支持分页或游标加载、加载态、空状态和失败重试。
- 查看帖子正文、图片、作者、圈子、话题、发布时间和互动数据。
- 从帖子进入所属圈子或作者主页。
- 点赞、取消点赞、收藏、取消收藏。
- 评论、回复、删除本人评论。
- 举报帖子、评论或回复。
- 分享链接；首期不建设复杂站内转发链路。

### 3.3 帖子发布

| 功能 | 内容 | 阶段 |
|---|---|---|
| 帖子编辑 | 标题、正文、图片、地点、可见范围 | MVP |
| 圈子与话题 | 必选一个圈子，可选该圈子下的多个已启用话题 | MVP |
| 图片处理 | 上传、排序、删除、封面选择、格式和大小校验 | MVP |
| 帖子预览 | 按实际详情页样式预览，不产生公开内容 | MVP |
| 发布校验 | 登录状态、必填项、长度、圈子权限、内容合规校验 | MVP |
| 草稿 | 自动保存或手动保存、恢复和删除草稿 | MVP |
| 编辑已发布帖子 | 修改后重新进入审核或风险检查 | 第二阶段 |

首期一篇帖子只属于一个主圈子，话题隶属于圈子。发布帖子时只能选择当前圈子下已启用的话题，不允许跨圈选择话题。是否允许“仅圈内可见”需要在权限模型阶段确认。

### 3.4 圈子互动

#### 圈子发现

- 按名称、简介、话题和标签快速搜索。
- 按分类筛选、推荐排序和活跃度排序。
- 展示圈子清单、封面、简介、人数、帖子数和加入状态。
- 加入/退出圈子；是否需要管理员审批由圈子类型决定。

#### 圈子详情

- 圈子介绍：名称、封面、简介、分类、标签、成员数、帖子数和管理者。
- 圈子置顶信息：圈规、公告和活动，支持展示顺序及有效期。
- 圈子信息流快速切换：

| 分区 | 定义 | 阶段 |
|---|---|---|
| 推荐 | 当前圈子内按推荐权重和热度排序 | MVP |
| 最新 | 当前圈子内按发布时间倒序 | MVP |
| 关注 | 当前圈子内、由用户已关注作者发布的帖子 | MVP |
| 精华 | 当前圈子内被评定为精华的帖子 | 延后 |

- 帖子正文、进入圈子、评论回复等能力复用帖子模块。
- 圈主/管理员入口、成员管理和圈子设置在第二阶段提供。

### 3.5 用户端公共能力

- 全局搜索：首期搜索圈子、帖子标题和话题；作者搜索可后续加入。
- 媒体上传：图片上传、压缩、格式校验、存储和安全访问。
- 登录拦截：发布、互动、加入圈子等操作统一要求登录。
- 权限反馈：无权限、内容已下架、内容审核中等状态有明确页面。
- 响应式适配：桌面端和移动端共享功能语义。
- 可观测性：前端错误采集、接口失败追踪和关键行为埋点。

## 4. 业务后端模块

### 4.1 用户与认证

- 注册、登录、退出、找回密码和会话管理。
- 当前用户资料读取与修改。
- 用户状态管理：正常、停用、注销中、已注销。
- 用户关注与取消关注、关注列表、粉丝列表及关注/粉丝计数。
- 用户行为权限校验，不信任前端提交的用户身份。
- 复用 RuoYi-Vue-Plus 的用户、角色、权限、登录日志和 Sa-Token 能力。

### 4.2 圈子服务

- 圈子增删改查、分类、标签、封面和状态管理。
- 圈子搜索、筛选、排序和详情查询。
- 加入、退出、成员查询和成员数量维护。
- 圈主、管理员、普通成员等圈内角色与权限。
- 圈子公告/置顶信息的创建、编辑、排序、有效期和上下线。
- 圈子关闭或冻结后，控制新加入、发帖和历史内容可见性。

### 4.3 帖子服务

- 帖子的创建、预览、发布、查询、修改、逻辑删除和恢复。
- 关联一个主圈子及该圈子下的多个话题，后端必须校验话题归属关系。
- 图片顺序、封面、可见范围和发布状态管理。
- 首页、圈子详情、作者主页等场景复用统一信息流查询。
- 推荐权重、运营置顶、圈内置顶分别管理，避免混为一个字段或动作。
- 违规内容采用隐藏/下架并保留审核证据；物理删除仅用于依法清除或数据生命周期任务。

建议的帖子业务状态（仅定义语义，不代表最终字段）：

```text
草稿 → 待审核/风险检查 → 已发布
                    ↘ 已驳回
已发布 → 已下架 / 作者删除 / 管理员删除
```

### 4.4 互动服务

- 帖子点赞与取消点赞，保证重复请求幂等。
- 帖子收藏与取消收藏。
- 评论、回复、删除本人评论和管理侧隐藏。
- 评论树首期建议只展示两级：一级评论和回复；数据关系可保留扩展能力。
- 帖子、评论和回复举报。
- 互动计数采用统一口径，并处理并发更新与数据校准。

### 4.5 话题与搜索

- 话题是圈子的下属资源，由圈子管理者或运营人员维护。
- 话题的创建、查询、修改、停用、别名、圈内排序和热度统计。
- 发布时只返回当前圈子下已启用的话题，支持在当前圈子内按关键词检索。
- 圈子详情可按话题筛选帖子；全局搜索可以聚合展示同名话题，但不改变话题的圈子归属。
- 首期可使用数据库检索；内容规模增长后再引入独立搜索引擎。
- 搜索结果必须应用内容可见性、审核状态和用户权限过滤。

### 4.6 媒体服务

- 上传凭证或后端上传接口、文件元数据和业务引用关系。
- 图片类型、体积、尺寸、数量和恶意文件检测。
- 原图、压缩图、缩略图的处理策略。
- 内容删除后媒体延迟回收，避免草稿或其他内容仍在引用。

### 4.7 审核与合规

- 帖子、评论和回复统一进入内容安全流程。
- 支持机器风险检查、人工审核、用户举报和运营主动巡检。
- 建议首期采用“高风险先审、普通内容发布后巡检”，避免所有内容同步人工审核阻塞发布。
- 审核结果至少区分通过、驳回、下架、恢复和待复核。
- 保存命中规则、处理原因、处理人、处理时间和申诉/复核记录。
- 后台操作进入审计日志，禁止无痕修改审核结果。

### 4.8 信息流分发、推荐与排行

#### 一期：基础信息流分发

- MVP 只建设可解释的基础分发规则：发布时间、基础互动热度、运营权重和去重，用于支撑首页及圈子的“推荐”分区。
- 最新信息流严格按时间排序，不受推荐权重影响。

#### 二期：推荐与排行

- 第二阶段建设热点帖子、热点圈子和排行能力，并明确近 24 小时、7 天、30 天等统计窗口。
- 个性化推荐、用户兴趣画像、推荐算法和实验平台均放到第二阶段，在有足够真实行为数据后建设。

### 4.9 通知服务（第二阶段）

- 评论、回复、点赞、关注、审核结果等站内通知。
- 未读数、通知列表、已读和批量已读。
- 邮件或推送通知后续通过统一通知事件扩展。

## 5. 运营管理后台

### 5.1 用户管理

- 用户列表、搜索、详情、状态调整和角色查看。
- 查看注册来源、最近登录、内容贡献和违规记录。
- 停用/恢复账号；高风险操作需要权限控制和操作原因。
- 不允许后台查看密码、验证码等敏感凭证。

### 5.2 圈子管理

- 圈子增删改查、分类标签、状态、圈主和管理员配置。
- 圈子下属话题的增删改查、启停和排序。
- 圈子公告/置顶信息管理。
- 成员管理、禁言、移出和加入审批（第二阶段）。
- 圈子推荐权重和首页展示配置。

### 5.3 帖子管理

- 帖子检索、详情查看、状态筛选和批量处理。
- 下架、恢复、逻辑删除和违规原因记录。
- 首页推荐、圈内推荐、首页置顶和圈内置顶分别配置。
- 查看作者、圈子、话题、互动数据和审核历史。

### 5.4 评论与回复管理

- 评论/回复检索、上下文查看、审核状态和举报记录。
- 隐藏、恢复、逻辑删除和违规原因记录。
- 从评论定位所属帖子、作者和父评论。

### 5.5 合规审核工作台

- 待审核队列、举报队列、机器命中队列和复核队列。
- 按风险等级、内容类型、圈子和时间筛选。
- 审核通过、驳回、下架、恢复、批量处理和备注。
- 审核权限、操作日志和处理时效统计。

### 5.6 运营数据

| 数据域 | 首期指标 | 后续扩展 |
|---|---|---|
| 用户 | 新增、活跃、留存、注册来源、地域分布 | 年龄段、兴趣偏好、用户分层 |
| 帖子 | 发布量、通过率、互动率 | 热点帖子、排行、内容质量评分、传播路径 |
| 圈子 | 新增成员、活跃成员、发帖量 | 热点圈子、排行、圈子健康度、成员留存 |
| 审核 | 待审量、违规率、处理时长、举报命中率 | 规则效果、误杀率 |
| 设备 | Web/移动端、系统、浏览器、机型（可获得时） | 跨端路径分析 |

用户画像的建设约束：

- 年龄段只有在用户主动填写或合法授权来源存在时才统计，不从其他信息推断。
- 地域优先使用用户主动填写的城市；IP 归属地只用于粗粒度统计并按隐私规则处理。
- 机型和系统来源于必要的客户端信息，不建设跨站指纹识别。
- 所有画像字段都要先明确业务用途、保留期限、访问权限和用户隐私说明。

## 6. 角色与权限边界

| 角色 | 主要能力 |
|---|---|
| 游客 | 浏览公开首页、圈子和帖子，使用公开搜索 |
| 注册用户 | 发布、互动、收藏、关注用户、加入圈子、维护个人资料 |
| 圈主/圈子管理员 | 维护圈子资料、公告、成员和圈内内容秩序 |
| 内容运营 | 配置推荐/置顶、维护圈子和运营内容 |
| 审核员 | 处理审核、举报、下架和恢复，不管理系统配置 |
| 平台管理员 | 用户、角色、权限和平台配置管理 |

具体权限点、数据权限和互斥规则在下一阶段单独设计。

## 7. 建设阶段建议

### 7.1 MVP：跑通真实业务闭环

- 邮箱注册、密码登录、找回密码、我的中心基础资料。
- 用户关注/取消关注、关注列表、粉丝列表和关注/粉丝计数。
- 圈子搜索、清单、详情、加入/退出和公告展示。
- 推荐/关注/最新信息流、帖子详情和进入圈子。
- 帖子发布、草稿、图片上传、圈子及圈内话题选择、预览。
- 点赞、收藏、评论、回复和举报。
- 运营后台的用户、圈子、帖子、评论基础管理。
- 帖子及评论审核、违规下架、审核记录和操作日志。
- 基础运营指标。

### 7.2 第二阶段：增强推荐与运营

- 编辑已发布帖子和消息通知。
- 圈主/管理员、成员管理、禁言和加入审批。
- 热点帖子、热点圈子、排行榜及统计窗口配置。
- 个性化推荐、用户兴趣画像、推荐算法、实验平台和数据校准。
- 更完整的运营看板。

### 7.3 延后能力

- 精华体系。
- 更复杂的自动人群分层和跨场景智能推荐。
- 多层嵌套评论展示。
- 微信扫码登录（其独立设计保留，按产品优先级接入）。

## 8. 需要产品确认的问题

1. 圈子是全部公开加入，还是支持需审批、私密等类型？圈子由管理员统一维护。
2. 帖子是否允许“仅圈内成员可见”？
3. 圈子详情的“关注”分区，是否定义为“我关注的作者在本圈发布的帖子”？
4. 发布内容采用全部先审、全部后审，还是高风险先审的混合模式？
5. 评论是否允许图片，首期是否需要 @ 用户？
6. 圈子话题由圈主/圈子管理员维护，还是只允许平台运营人员维护？
7. 圈主和圈子管理员是否在 MVP 开放给普通用户？
8. 后台“删除”是否统一改成“下架/逻辑删除”，物理删除只由系统任务执行？
9. 用户画像中的年龄段从何处获得，是否确有首期业务用途？

## 9. 下一步设计顺序

本稿确认后，按以下顺序继续，避免直接从页面跳到建表：

1. 确认 MVP 范围和第 8 节产品问题。
2. 编写核心用例、角色权限矩阵和内容状态流转。
3. 划分领域对象及对象之间的关系。
4. 设计接口契约、分页方式、错误码和幂等规则。
5. 确定数据库表结构、索引、逻辑删除和审计字段。
6. 输出增量 SQL、前后端迭代计划和验收用例。
