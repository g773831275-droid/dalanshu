# 首页 API 契约

## 1. 文档信息

- 页面：普通用户端首页 `/`
- API 版本：v1
- Base URL：`/api/v1`
- 数据格式：`application/json`
- 字段命名：camelCase
- 实现基准：当前后端 `DalanbookV1Controller` 与 `DalanbookApiService`

首页现有分类、信息流、左侧导航与圈子推荐接口继续沿用。本次补齐导航栏搜索交互，直接使用后端已有的搜索建议接口；当前版本不把“建议”伪装成完整搜索结果页。

## 2. 获取搜索建议

### 2.1 请求

```http
GET /api/v1/search/suggest?q=AI
```

该接口允许匿名访问。`q` 去除首尾空格后参与搜索；空字符串返回热门搜索词。

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `q` | `string` | 否 | 搜索关键词，前端输入防抖 250ms 后发送 |

### 2.2 响应

```json
{
  "suggestions": [
    { "type": "keyword", "id": null, "text": "AI" },
    { "type": "circle", "id": "ai-tools", "text": "AI 工具圈" },
    { "type": "post", "id": "10001", "text": "我用了 30 天 AI Agent" }
  ]
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `suggestions` | `Suggestion[]` | 是 | 最多 10 条 |
| `Suggestion.type` | `string` | 是 | `hot`、`keyword`、`circle` 或 `post` |
| `Suggestion.id` | `string \| null` | 是 | 圈子/帖子 ID；关键词类为 `null` |
| `Suggestion.text` | `string` | 是 | 展示文本 |

后端行为：

- `q` 为空时返回 `hot` 热门词。
- `q` 非空时先返回一条 `keyword`，再返回最多 4 个名称匹配的圈子与 5 个标题匹配的帖子。
- 圈子仅搜索已发布数据，帖子仅搜索已发布数据。

## 3. 前端交互

- 输入框聚焦后请求建议；空输入展示热门词。
- 点击 `hot` 只把热词回填到输入框并继续查询。
- 点击 `circle` 跳转 `/circles/{id}`；点击 `post` 跳转 `/posts/{id}`。
- `keyword` 用于说明当前搜索词，不提供不存在的“完整结果”跳转。
- 按 Enter 时优先打开当前第一条可跳转的圈子或帖子建议。
- 请求失败时搜索框保持可用，并展示“搜索建议加载失败”；不影响首页信息流。

React Query Key：

```text
["home", "search-suggest", normalizedQuery]
```

## 4. 后续完整搜索边界

当前后端没有完整搜索结果接口，也没有结果页所需的游标、类型筛选和排序能力。如果后续建设完整搜索，应单独定义分页接口，不应复用 `/search/suggest` 承载结果列表。

## 5. 本地 Mock

`VITE_API_MODE=mock` 且运行开发服务器时，前端返回与真实接口相同的 `Suggestion[]` 结构，并支持圈子和帖子标题匹配。正式构建始终请求真实接口。
