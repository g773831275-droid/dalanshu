# 登录注册页与登录弹窗 API 契约

## 1. 文档信息

- 页面：独立登录注册页 `/auth`
- 组件：全局登录注册弹窗 `AuthModal`
- API 版本：v1
- Base URL：`/api/v1/auth`
- 数据格式：`application/json`
- 字段命名：请求 camelCase；令牌响应使用 snake_case
- 实现基准：当前后端 `AuthController`、`CaptchaController` 与 `DalanbookV1Controller`

独立页面和全局弹窗共用同一套前端 API。前端只展示邮箱密码登录与邮箱验证码注册，不展示手机号、微信、Apple、Google 或其他第三方登录方式。

## 2. 邮箱认证流程

登录：

```text
获取图形验证码 → 邮箱 + 密码登录 → 保存令牌 → 获取当前用户 → 进入目标页面
```

注册：

```text
获取图形验证码 → 获取邮箱验证码 → 邮箱注册并自动登录 → 保存令牌 → 获取当前用户 → 进入目标页面
```

登录弹窗成功后关闭弹窗，并跳转到触发登录时记录的 `redirect`；独立页面成功后跳转到 URL 查询参数中的 `redirect`，缺省返回首页。

## 3. 获取图形验证码

### 3.1 请求

```http
GET /api/v1/auth/code
```

### 3.2 响应

验证码开启：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "captchaEnabled": true,
    "uuid": "captcha_uuid",
    "img": "base64_encoded_image"
  }
}
```

验证码关闭：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "captchaEnabled": false
  }
}
```

前端收到没有 `data:` 前缀的 `img` 时，按 GIF Base64 补充：

```text
data:image/gif;base64,{img}
```

## 4. 获取邮箱验证码

### 4.1 请求

```http
GET /api/v1/auth/email/code?email=user%40example.com&purpose=register&uuid=captcha_uuid&code=abcd
```

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `email` | `string` | 是 | 标准化为小写的邮箱地址 |
| `purpose` | `string` | 是 | `register` 注册；`recover` 找回密码 |
| `uuid` | `string` | 是 | 图形验证码标识 |
| `code` | `string` | 是 | 用户输入的图形验证码 |

注册页和弹窗固定传 `purpose=register`。相同邮箱 60 秒内最多请求一次。

### 4.2 响应

生产环境发送成功：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {}
}
```

开发环境未配置 SMTP 且后端允许回显时：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "devCode": "123456"
  }
}
```

存在 `devCode` 时，前端自动填入邮箱验证码输入框。生产环境不得回显验证码。

## 5. 邮箱密码登录

### 5.1 请求

```http
POST /api/v1/auth/login
Content-Type: application/json
clientid: e5cd7e4891bf95d1d19206ce24a7b32e
```

```json
{
  "account": "user@example.com",
  "password": "user-password",
  "clientId": "e5cd7e4891bf95d1d19206ce24a7b32e",
  "grantType": "password",
  "uuid": "captcha_uuid",
  "code": "abcd"
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `account` | `string` | 是 | 当前前端只允许邮箱，提交前去除空格并转小写 |
| `password` | `string` | 是 | 前端 6～64 位；当前后端密码登录校验 5～30 位 |
| `clientId` | `string` | 是 | Web 客户端 ID |
| `grantType` | `string` | 是 | 固定 `password` |
| `uuid` | `string` | 条件必填 | 图形验证码开启时必填 |
| `code` | `string` | 条件必填 | 图形验证码开启时必填 |

后端密码策略兼容用户名和手机号，但当前产品前端不提供这些登录入口。

### 5.2 响应

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "access_token": "access_token_value",
    "refresh_token": "refresh_token_value",
    "expire_in": 86400,
    "refresh_expire_in": 2592000,
    "client_id": "e5cd7e4891bf95d1d19206ce24a7b32e"
  }
}
```

## 6. 邮箱注册

### 6.1 请求

```http
POST /api/v1/auth/register
Content-Type: application/json
clientid: e5cd7e4891bf95d1d19206ce24a7b32e
```

```json
{
  "email": "user@example.com",
  "emailCode": "123456",
  "password": "user-password",
  "clientId": "e5cd7e4891bf95d1d19206ce24a7b32e",
  "grantType": "password"
}
```

| 字段 | 类型 | 必填 | 后端约束 |
| --- | --- | --- | --- |
| `email` | `string` | 是 | 合法邮箱，去除空格并转小写，不能重复 |
| `emailCode` | `string` | 是 | 6 位注册邮箱验证码 |
| `password` | `string` | 是 | 8～30 位 |
| `clientId` | `string` | 是 | Web 客户端 ID |
| `grantType` | `string` | 是 | 固定 `password` |

成功后后端创建账号并直接返回与登录相同的令牌响应，不需要再次请求登录接口。

## 7. 获取当前用户

### 7.1 请求

```http
GET /api/v1/auth/me
Authorization: Bearer <accessToken>
```

### 7.2 响应

```json
{
  "id": "10001",
  "nickname": "大蓝书用户",
  "avatar": "https://example.com/avatar.webp",
  "bio": "",
  "gender": "unknown",
  "location": "",
  "followerCount": 0,
  "followingCount": 0,
  "postCount": 0,
  "isFollowing": false,
  "createdAt": "2026-07-16T08:00:00Z"
}
```

前端认证状态只保存 `id`、`nickname → name` 和可选 `avatar`。

## 8. 刷新令牌

访问令牌失效并返回 `401` 时，前端自动尝试：

```http
POST /api/v1/auth/refresh
Content-Type: application/json
```

```json
{
  "refreshToken": "refresh_token_value"
}
```

成功返回一组新的访问令牌和刷新令牌。刷新令牌采用 rotation：旧刷新令牌成功使用后立即失效。刷新失败时前端清除本地令牌。

## 9. 退出登录

```http
POST /api/v1/auth/logout
Authorization: Bearer <accessToken>
```

无论后端退出请求是否成功，前端最终都清除本地访问令牌、刷新令牌和用户状态。

## 10. 错误与前端处理

认证相关接口主要使用 RuoYi 响应包装：

```json
{
  "code": 500,
  "msg": "邮箱或密码错误",
  "data": null
}
```

| 场景 | 前端处理 |
| --- | --- |
| 邮箱格式、密码长度或确认密码错误 | 表单字段下方显示本地校验信息，不发送请求 |
| 图形验证码缺失或错误 | 显示接口信息并刷新图形验证码 |
| 邮箱验证码错误或过期 | 保留注册表单内容，显示接口信息 |
| 邮箱已经注册 | 保留注册表单内容，提示切换登录 |
| 登录失败 | 保留邮箱，显示错误并刷新图形验证码 |
| `401` 且存在刷新令牌 | 自动刷新令牌并重试原请求一次 |

## 11. 前端本地 Mock

`dalanbook-frontend/.env.local` 设置以下内容时，图形验证码、邮箱验证码、登录、注册、当前用户和退出登录使用本地 Mock：

```dotenv
VITE_API_MODE=mock
```

Mock 约定：

- 图形验证码关闭。
- 注册邮箱验证码固定为 `123456`，点击获取后会自动填入。
- 演示账号：`demo@dalanbook.com`。
- 演示密码：`dalanbook123`。
- 新注册账号在当前开发会话内可以立即登录。

Mock 仅在 `npm run dev` 生效；正式构建和 `VITE_API_MODE=real` 始终请求真实后端。
