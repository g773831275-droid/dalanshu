# 消息页面 API 契约

## 1. 页面范围

消息页面仅展示以下三种站内互动通知：

| `type` | 页面文案 | 点击目标 |
| --- | --- | --- |
| `post_like` | 点赞了你的帖子 | `/posts/{post.id}` |
| `post_favorite` | 收藏了你的帖子 | `/posts/{post.id}` |
| `user_follow` | 关注了你 | `/u/{actor.id}` |

评论、回复、系统公告、审核结果和私信不属于本页面。后端通知列表应仅向该页面返回上述三种类型；前端仍会过滤未知类型，避免错误消息进入页面。

所有接口均要求登录，并携带：

```http
Authorization: Bearer <accessToken>
clientid: <clientId>
```

接口沿用后端现有的 `/api/v1/notifications` 路径。

## 2. 数据结构

### 2.1 NotificationActor

```json
{
  "id": "1024",
  "name": "林深",
  "avatarUrl": "https://example.com/avatar.jpg",
  "avatarColor": "#315C7B"
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | `string` | 是 | 触发通知的用户 ID |
| `name` | `string` | 是 | 用户昵称 |
| `avatarUrl` | `string` | 否 | 用户头像地址 |
| `avatarColor` | `string` | 是 | 头像缺失时的占位背景色 |

### 2.2 NotificationPost

```json
{
  "id": "p1",
  "title": "我用了 30 天 AI Agent，真正有用的是这 4 个场景",
  "cover": "https://example.com/post-cover.jpg"
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | `string` | 是 | 帖子 ID |
| `title` | `string` | 是 | 帖子标题 |
| `cover` | `string` | 否 | 帖子封面 |

### 2.3 Notification

```json
{
  "id": "n_01",
  "type": "post_like",
  "payload": {
    "actor": {
      "id": "1024",
      "name": "林深",
      "avatarUrl": "https://example.com/avatar.jpg",
      "avatarColor": "#315C7B"
    },
    "post": {
      "id": "p1",
      "title": "我用了 30 天 AI Agent，真正有用的是这 4 个场景",
      "cover": "https://example.com/post-cover.jpg"
    }
  },
  "readAt": null,
  "createdAt": "2026-07-16T08:30:00Z"
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | `string` | 是 | 通知 ID |
| `type` | `post_like \| post_favorite \| user_follow` | 是 | 通知类型 |
| `payload.actor` | `NotificationActor` | 是 | 触发通知的用户 |
| `payload.post` | `NotificationPost` | 点赞/收藏时是 | 关联帖子；关注通知不返回 |
| `readAt` | `string \| null` | 是 | UTC 已读时间；未读为 `null` |
| `createdAt` | `string` | 是 | UTC 创建时间 |

后端生成通知时不得向用户推送其本人触发的点赞、收藏或关注操作。相同用户对同一对象取消后再次操作，可生成一条新通知；单次幂等重试不得重复生成。

## 3. 获取未读数

```http
GET /api/v1/notifications/unread-count
```

### 200 Response

```json
{
  "count": 3
}
```

`count` 只统计 `post_like`、`post_favorite`、`user_follow` 三种未读通知。

## 4. 获取消息列表

```http
GET /api/v1/notifications?cursor=&limit=20
```

### Query

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `cursor` | `string` | 否 | - | 上一页返回的游标 |
| `limit` | `integer` | 否 | `20` | 每页数量，范围 `1–50` |

列表按 `(createdAt, id)` 倒序排列。

### 200 Response

```json
{
  "items": [
    {
      "id": "n_01",
      "type": "post_like",
      "payload": {
        "actor": {
          "id": "1024",
          "name": "林深",
          "avatarColor": "#315C7B"
        },
        "post": {
          "id": "p1",
          "title": "我用了 30 天 AI Agent，真正有用的是这 4 个场景"
        }
      },
      "readAt": null,
      "createdAt": "2026-07-16T08:30:00Z"
    }
  ],
  "nextCursor": "eyJjcmVhdGVkQXQiOiIuLi4ifQ",
  "hasMore": true
}
```

## 5. 标记单条消息已读

```http
PUT /api/v1/notifications/{id}/read
```

请求体为空。重复调用应保持幂等。

前端点击未读消息时先乐观更新消息列表和全局未读数，再跳转到关联帖子或用户主页；接口失败时回滚本地状态，接口完成后重新校准列表和未读数。已读消息重复点击不会再次减少未读数。

### 204 Response

无响应体。

## 6. 错误响应

接口沿用项目统一错误结构：

```json
{
  "code": "NOTIFICATION_NOT_FOUND",
  "message": "通知不存在"
}
```

| HTTP 状态 | `code` | 场景 |
| --- | --- | --- |
| `401` | `UNAUTHORIZED` | 未登录或令牌失效 |
| `400` | `INVALID_CURSOR` | 游标无效 |
| `404` | `NOTIFICATION_NOT_FOUND` | 通知不存在或不属于当前用户 |

## 7. 前端 Mock

开发环境配置 `VITE_API_MODE=mock` 时使用本地消息数据：

- 提供点赞、收藏、关注三种通知；
- 支持游标分页；
- 支持单条已读并同步更新未读数；
- 不依赖 MySQL 或后端通知数据。

## 8. 当前后端实现

- 首次成功点赞、收藏或关注时生成对应通知，幂等重试不重复生成；
- 用户对自己的帖子操作不生成通知；
- 点赞和收藏通知包含 `payload.actor` 与 `payload.post`，关注通知包含 `payload.actor`；
- 消息列表和未读数只统计 `post_like`、`post_favorite`、`user_follow` 三种类型；
- 单条已读接口校验通知归属并保持幂等。
