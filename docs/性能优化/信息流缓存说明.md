# 信息流缓存说明

## 目标

首页首屏具有高重复访问特征。项目使用 Redis 缓存推荐、最新频道的第一页公共数据，减少首页高峰期重复的帖子、圈子、作者、统计及视频批量查询。

## 缓存范围

缓存入口为 `DalanbookHomeFeedCacheService#loadFirstPage`，缓存组为：

```text
global:dalanbook:home_feed
```

当前规则：

- 缓存 `recommend`、`latest` 频道的第一页。
- 分类、频道和 `limit` 共同组成缓存键。
- TTL 为 30 秒。
- 最多保留 500 个首屏组合。
- 关闭 JVM 本地二级缓存，保证以后增加后端实例时都以 Redis 为准。
- `following` 关注流不缓存。
- 带游标的第二页及后续分页不缓存。

## 缓存内容与数据安全

公共快照只保存：

- 帖子公开字段。
- 圈子公开字段。
- 作者 ID、昵称和头像 `ossId`。
- 帖子统计。
- 视频公开展示信息。

快照不保存 `SysUser` 对象，因此不会把密码、手机号、邮箱等字段写入该业务缓存。以下内容也不缓存：

- 当前用户的点赞、有用、收藏状态。
- TOS 私有桶临时签名 URL。
- 关注流和其他个性化列表。

每次请求仍会查询当前登录用户对这一页帖子的互动状态，并实时生成当前有效的图片访问地址，避免用户状态串用及签名过期。

## 一致性

普通图片帖子成功发布、视频帖子处理完成并发布后，会在事务成功提交后清空首页缓存。点赞数、收藏数、昵称等非结构性变化允许最多 30 秒延迟；用户自己的互动开关状态不受缓存影响。

若主动清理 Redis，应通过应用的缓存清理入口清空 `global:dalanbook:home_feed` 缓存映射，
不要使用模糊扫描删除线上 Redis 全库键。`global:` 前缀表示该公共信息流不依赖登录租户，
避免匿名请求被写入空租户缓存空间。

## 验证

```bash
mvn -pl ruoyi-modules/ruoyi-system -am test -DskipTests=false
```

上线后应对比缓存启用前后的首页 P95、MySQL 查询次数、Hikari 活跃连接数和 Redis 延迟。缓存只减少重复查询，不替代数据库索引和慢 SQL 治理。
